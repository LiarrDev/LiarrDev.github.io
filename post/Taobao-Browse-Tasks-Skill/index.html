把薅羊毛交给 AI：我做了个自动刷淘宝任务的 SKILL

不知道你有没有做过 App 里的薅羊毛任务：用一点小奖品或优惠吸引用户参与，用户却要每天花不少时间刷激励任务。以淘宝为例，芭芭农场要逛店，淘金币要“搜一搜”，各种会场要停留 15~30 秒领奖励。单个任务不过半分钟，但一天攒下来能吃掉一两个小时。我每天上下班在地铁上，总能看到有人机械地刷着这些任务。

淘金币 芭芭农场

坦白说，这些任务确实能薅到一些羊毛，但如果换算成时间成本，性价比并不高。我就在想：把这些碎片化时间用来看几篇文章，会不会更有价值？

小孩子才做选择，成年人全都要。羊毛和时间，我都不放过！

上次介绍过 Mobile MCP，一个由 AI 驱动的强大移动端自动化工具。最近我基于它做了一个自动刷淘宝任务的 Skill：只需把手机连接电脑，就可以让 AI 接管任务流程，你则可以利用这段时间做更有意义的事，尤其适合上班后挂在后台运行。

『taobao-browse-tasks』不是一个独立 App，而是一个 Agent Skill，它的组成很轻量，不过是若干份参考文档和 Python 脚本，告诉 AI 怎么理解任务、如何决策、怎么操作。加载到任何支持 Agent Skill 的客户端，只需要说一句“刷淘宝任务”或者“做芭芭农场”，Agent 就会自己识屏、点任务、停留、返回，并把每一步记进日志。

这个 Skill 做得很克制，只做浏览类任务，这也是激励任务的大头，跳转第三方应用、游戏、关注等一概跳过，避免干扰和风险。

类型 处理
BROWSE 浏览 / 逛店 / 看会场 ✅ 执行
GAME 去玩 / 挑战 / 抽奖 / 合成 ⏭ 跳过
THIRD_PARTY 支付宝 / 头条 / 百度 / 淘宝特价版 ⏭ 跳过
OTHER 下单 / 加购 / 关注 / 邀请 / 看直播 ⏭ 跳过

做这个 Skill 过程中也踩了一些坑。淘宝的页面架构也许比较混乱，有些是 H5，有些用的是古早的 Weex。而 Mobile MCP 默认通过 dump 读控件树，在部分任务列表中会出现“滑动后读到的控件树仍是滑动前状态”的情况，导致 AI 无法正确识别任务。幸好 Mobile MCP 有回退机制，会自动切换到截图模式，通过图像识别读取位置。偶尔 AI 也会因为计算坐标偏差而点错，好在它能自行纠错，点错就返回。

比技术更难对付的是淘宝的风控模型。众所周知，阿里系产品的体验常被吐槽，但安全风控能力确实很强。早些年我尝试用 Auto.js 写脚本刷淘宝任务，很快就被风控降权了，这次依然绕不开这个问题。风控是个黑盒，我们无法知道它的具体规则，停留过短、路径单一、频次过高等等行为都可能被标记，只能通过猜测和推断调整行为来规避，因此目前仍无法完全避免，所以我还定了规则控制每轮任务的上限，尽量减少触发风控的机会，你也可以通过 Agent 修改它。

使用也很简单，通过下面的命令安装 Skill：

➜   git clone https://github.com/LiarrDev/taobao-browse-tasks.git ~/.agents/skills/taobao-browse-tasks

或者直接把项目丢给 Agent 就好，它会告诉你怎么做。

目前主流程覆盖芭芭农场和淘金币任务，外加红包签到和小黑盒；另外，最近不是双十一嘛，我也加了两个对应的临时活动模块，你可以跑起来试试。

由于大模型主要参与决策，不需要很长的推理，整个任务跑下来并不会消耗太多 Token；但建议使用聪明一点的模型，能明显减少决策时间。

如果你追求极致的时间效率，这个 Skill 也许并不是最佳选择。它本质上是一个带安全边界的具身 Agent 最小闭环：看屏幕 → 做动作 → 验证结果 → 记账。实际任务执行时间可能只占流程的一半，也就是说，一个 15 秒的任务，真正跑下来可能要超过 30 秒。

它的核心价值是 “省注意力”，而不是“省时间”。

每天省下的不是那一两个小时，是“还得惦记着去做任务”的那份心理负担。
