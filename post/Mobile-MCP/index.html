从脚本到 Agent：Mobile MCP 让 AI 直接操作手机

自动化测试几乎与应用同时诞生。以 Android 为例，最早可以追溯到 MonkeyRunner：它依赖屏幕坐标点击，稳定性和维护成本都不理想。直到 UI Automator 推出，程序第一次能“看”到界面控件树，按控件 ID 和文本去点击，才算脱离“坐标地狱”。后来，Appium 把 WebDriver 那套搬到移动端，一套 API 同时管理 iOS 和 Android，成为跨平台统一的里程碑。国内也热闹过一阵：网易 Airtest 走图像识别加控件的双路线，Auto.js 用无障碍服务跑 JS 脚本，后来因监管原因逐渐退出主流。

但无论哪一代方案，有个老问题一直没解决：它们都是“人写脚本，机器执行”。开发者必须先想清楚每一步点哪里、等什么，再翻译成代码。随着 AI Agent 兴起，一个自然的问题出现了：能不能直接告诉 Agent「去把某某 App 的登录流程走一遍」，让它自己看屏幕做决策？

2025 年 12 月 1 日，字节与中兴合作推出搭载豆包手机助手技术预览版的 nubia M153，最大卖点是 AI 可以替用户操作手机。但发布没几天，麻烦就来了：部分用户在用豆包操作微信后，账号被强制退出，出现登录环境异常提示；淘宝等应用也被曝出现登录受阻、人机验证等情况；部分银行 App 发出风险提醒。

12 月 5 日，豆包宣布调整金融、游戏、刷激励等场景的自动化操作能力，并提出与应用厂商共同制定操作规则。

2026 年 9 月 14 日，豆包推出《屏幕自动化操作声明协议（SAEP）》，让第三方应用自主决定是否授权屏幕自动化操作。30 天公示期结束后，豆包手机助手公布了拒绝操作的应用清单，共有 155 款应用明确拒绝操作，其中包括腾讯系 66 款和阿里系 23 款，两个大厂占拒绝名单的 57%。

考虑到用户隐私、广告转化等因素，各应用厂商拒绝授权豆包的 SAEP 也无可厚非。但自动化操作的需求一直存在，而 AI 操作手机把这个需求带到了新的高度：自动化脚本只能沿既定路径执行，AI 则能根据用户指令和模型推理动态决策。

Mobile MCP 正是在这一技术趋势下出现的一个代表性方案——它不解决生态授权问题，但把“让Agent直接驱动手机”这件事在技术层面标准化了。

Mobile MCP 由 Mobile Next 团队开源，目前在 GitHub 上已获得 10K+ Star。它做的事很直接：把 MCP 的工具调用从桌面浏览器延伸到真机和模拟器，同一套工具覆盖 iOS 与 Android，让 Agent 不再只会点网页，而能直接驱动手机上的原生 App 完成自动化和数据采集。对于希望把桌面智能体能力延伸到移动端的团队，它把“驱动设备”这一层标准化了。

Talk is cheap. 直接上效果。

Mobile MCP 省 Token 的思路很清晰：默认读取无障碍树（Accessibility Tree）——一种结构化节点描述，告诉模型屏幕上有什么元素、各自是什么角色、位于哪一层。这与浏览器的无障碍树同源：模型拿到的是语义，不是像素。因此，常规的步骤规划与点击完全不需要调用视觉模型，也就不消耗昂贵的 Image Token。只有当无障碍树确实说不清、必须看具体画面时，才退回「截图 + 坐标」的路线。这个退路把视觉成本压缩在必要时刻，而不是每一步都烧一张图。对需要运行成千上万次的任务来说，这种取舍会直接反映在账单上。

Mobile MCP 的架构如下：

安装不复杂，准备以下环境即可，多数移动开发者应该都已具备：

  • Xcode Command Line Tools / Android Platform Tools
  • Node.js v20+
  • 支持 MCP 的 Agent

然后配置 MCP：

{
  "mcpServers": {
    "mobile-mcp": {
      "command": "npx",
      "args": ["-y", "@mobilenext/mobile-mcp@latest"]
    }
  }
}

工具大致分为以下几组：

  • 设备管理：列出设备、读屏幕分辨率、横竖屏、折叠屏折叠、GPS 位置伪造、剪贴板读写。
  • 应用管理：列出 / 启动 / 终止 / 安装（.apk / .ipa / .app / .zip）/ 卸载，看当前前台 App。
  • 屏幕交互：列出界面元素、tap / 双击 / 长按 / 滑动、截图、录屏。
  • 输入与导航：打字（可带提交）、按硬件键（HOME / BACK / 音量）、开 URL。
  • 日志与崩溃：Android Logcat、iOS Unified Log、崩溃报告。
  • 批处理：mobile_batch_commands 一次调用跑一串工具，省掉来回往返。
  • 云真机：Mobile Next Cloud，直接对云上的真机 iOS/Android 跑同一套工具，本地不用搭环境。

这些能力基本覆盖了移动端日常自动化需求。

如果团队要把 AI Agent 接入移动工作流，又不想为每个项目分别写一套平台集成，Mobile MCP 把“驱动设备”这一层封装进了一个标准 MCP 服务器。即使只是临时写个一次性自动化脚本，用几句话描述清楚，它也能快速完成目标。
